Stage 0 · Trigger & Early Exit

5 nodes · eliminates ~70% of pipeline runs on quiet ticks
1 · Timer TriggerInput
Fires the pipeline every 60 seconds, 24×7.
Interval: 60s · TZ: Asia/Kolkata
Out: {tick_id, ts_utc, tenant_id}
2 · Fetch Channel SnapshotKnowledge Retrieval
Parallel pull from Shopify REST, Amazon SP-API, POS CSV on S3.
Timeout: 8s per source · Fan-out: parallel
Out: {shopify:[...], amazon:[...], pos:[...]}
3 · Snapshot Hash Check v2Custom Code
MD5 hashes the snapshot, compares with Redis-stored previous hash.
Store: Redis SETEX 180s
Out: {changed: bool, hash}
4 · Changed Since Last Run?Condition
YES → Stage 1. NO → node 5 (exit).
Expr: $.changed == true
5 · Quiet Tick AckOutput
Writes a "skipped" metric row for dashboard observability.
Out: {tick_id, status:"skipped", reason:"no_change"}

Stage 1 · Sync Agent

4 nodes · harmonizes 3 channel schemas into one canonical record
6 · Normalize SchemaCustom Code
Flattens vendor-specific field names (variant_sku → sku, etc.) before LLM.
Map: shopify/amazon/pos → canonical
Out: [{sku, qty, price, source}]
7 · SKU Master LookupKnowledge Retrieval
Pulls canonical SKU aliases from Postgres for grounding.
SQL: SELECT canonical_sku, aliases FROM sku_master WHERE tenant_id=:t
8 · Sync Agent LLMLLM Step
Resolves fuzzy SKU aliases to canonical IDs (RICE-5KG-V1 → RICE-5KG).
Model: Claude Haiku · temp 0 · JSON mode
System: "You are a SKU normalization agent..."
9 · Canonical Inventory JSONOutput Formatter
Emits the single canonical record Stage 2 consumes.
Schema: {sku, name, channels:{shopify, amazon, pos}}

Stage 2 · Conflict Agent

14 nodes · bandit-weighted rules, idempotent API, token-bucket safety, escalation
10 · Rule-Based Conflict DetectionCustom Code
Thresholds sampled from bandit + tenant calibrator — no hard-coded Rs.20 anymore.
Rules: price_delta > θ₁, oversell > θ₂
θ source: 10a × 10b (sampled)
10a · Bandit Posterior Store v3Memory
Beta(α,β) per rule-tenant. Thompson samples a weight each run.
Table: rule_posteriors(tenant_id, rule_id, alpha, beta)
Sample: np.random.beta(α+1, β+1)
10b · Tenant Calibrator v3Custom Code (nightly)
Computes P85 of tenant's own 30-day legitimate price moves. Replaces McKinsey citation.
SQL: percentile_cont(0.85) WITHIN GROUP (ORDER BY d)
Writes: tenant_thresholds
11 · Severity RouterClassifier / Router
Tags each conflict LOW / MED / HIGH by est. monetary impact.
HIGH: loss > Rs.10K · MED: Rs.1K-10K · LOW: <Rs.1K
12 · Any Conflicts Found?Condition
Short-circuits to Insight when conflict list is empty.
Expr: len($.conflicts) > 0
13 · Loop per Conflict v2Loop
Processes each conflict independently — a bad row can't poison the batch.
Mode: ForEach · parallelism=5 · err=continue
13a · Reserve Action Slot v3Custom Code
UNIQUE constraint on action_log enforces exactly-once at the DB level.
Key: md5(tenant|sku|type|channel|price|date)
DB refuses duplicate → skip branch
13b · Token Bucket Check v3Guardrail
Per-tenant Redis bucket: 50 tokens, refills 10/min. Empty = auto-mode OFF.
Algo: leaky bucket (RFC 2698)
Empty → route to node 17
13c · Auto-Mode Tripped Alert v3Guardrail
Pages owner, posts dashboard banner, logs incident.
Channels: Telegram + email + banner
14 · Post Resolution APITool
Calls Shopify PUT /variants or Amazon Feed API with idempotency key.
Retry: exp backoff 3x, jitter 200ms
Header: X-Idempotency-Key
15 · Log to conflict_logMemory
Immutable event row — Stage 3's retrieval source.
Cols: ts, tenant, sku, type, sev, delta, resolved_by
16 · Amount > Rs.50K?Condition
Human-in-the-loop gate for financially material fixes.
Basis: 3.5× avg daily SME revenue
17 · Telegram + SMS Handoff v2Human Handoff
Telegram first; 5-min no ACK → MSG91 SMS fallback. Tier-2/3 reality.
Channels: Telegram → SMS
Actions: APPROVE / SKIP
17a · Bandit Update v3Memory
On ACK → α+=1 (rule validated). On SKIP → β+=1 (rule over-fired). Feeds back to 10a.
Closes the loop. System self-tunes per tenant.

Stage 3 · Insight Agent

12 nodes · cold-start ready, calibrated threshold, dual-layer fact-verification
18 · 7-Day Conflict HistoryKnowledge Retrieval
Rolling week of conflicts, grounding context for the LLM.
SQL: WHERE ts > NOW() - INTERVAL '7 days'
18a · Cold-Start Gate v3Condition
Routes new tenants (<7 days) to peer cohort retrieval instead of thin own-data.
Expr: history_days >= 7
18b · Peer Cohort (Bayesian) v3Knowledge Retrieval
Anonymized same-vertical cohort. Bayesian shrinkage: λ = days/7.
Blend: λ·tenant + (1-λ)·cohort
Prompt flag: early_stage=true
19 · Few-Shot System Prompt v2Prompt Template
2 worked examples (pricing drift, oversell) locking JSON shape.
Out schema: {"bullet":"•...","confidence":0-1}
20 · Insight Agent LLMLLM Step
Produces the single most-visible artifact — the daily bullet.
Model: Claude Haiku · temp 0.3 · max 120 tokens
21 · Confidence >= threshold? v2Condition
Threshold is per-tenant (isotonic calibration), not fixed 0.7.
Source: tenant_thresholds.confidence
21a · Bullet Feedback Log v3Memory
Logs every (confidence, owner_accepted) pair for calibration.
Cols: ts, tenant, confidence, accepted
21b · Isotonic Calibrator v3Custom Code (nightly)
sklearn.isotonic fit. Threshold = lowest raw conf where precision ≥ 0.9.
Min samples: 200 · Cold start: 0.7
22 · 30-Day Deep History v2Knowledge Retrieval
Low-confidence fallback. Loops back to node 20 once (cap enforced).
Max re-queries: 1 per bullet
23 · Regex Fact-Verify v2Guardrail
Catches ₹, INR, K-suffix, decimals, case-insensitive SKU check.
Regex: (?:Rs\.?|₹|INR)\s?([\d,]+(?:\.\d+)?)[Kk]?
23a · LLM-as-Judge Verifier v3Guardrail
Second Haiku call extracts all claims; set-membership check. Independent verification.
Pattern: Zheng et al. 2023
Cost: ~₹0.02/bullet
24 · Dashboard JSONOutput
Payload React polls every 5s via Axios.
Schema: {ts, bullet, confidence, conflicts_today, revenue_saved_inr}

Stage 4 · Analyst Agent (Weekly)

7 nodes · dual-seed self-consistency + aggregate fact-verify
25 · Weekly TimerInput
Sunday 06:00 IST cron.
Cron: 0 6 * * 0 · TZ Asia/Kolkata
26 · 7-Day AggregateKnowledge Retrieval
Aggregated counters, not raw rows — keeps context small for Sonnet.
SQL: GROUP BY sku, type · ORDER BY rs_drift DESC · LIMIT 20
27 · Analyst Run ALLM Step
Claude Sonnet, seed 42 — weekly 5-bullet executive pattern memo.
Model: Sonnet · temp 0.4
Out: [{bullet, claim_set}]
27a · Analyst Run B v3LLM Step
Same prompt, seed 17. Used for self-consistency check.
Wang et al. 2022 pattern
27b · Self-Consistency Intersect v3Custom Code
Publishes only claims appearing in BOTH runs. Kills one-off hallucinations.
Op: claims_A ∩ claims_B
27c · Aggregate Fact-Verify v3Guardrail
Same regex + LLM-as-judge pattern as nodes 23/23a, against 7-day aggregate.
Rejects: bullets with unsourced Rs. or SKUs
28 · Executive Email + Pattern FeedOutput
SendGrid email + dashboard Pattern Feed widget.
Channels: SendGrid · pattern_feed table

★ Stage 5 · Mirror Agent (Hourly) — the 100th-point layer

6 nodes · watches the system's own signals, not business data
31 · Hourly Timer v3Input
The Mirror's heartbeat. Separate from the 60s main tick.
Cron: 0 * * * *
32 · System Metrics v3Knowledge Retrieval
Pulls confidence distribution, bucket trip count, rejection rate, contradictions.
No business data — system-only signals
33 · Drift Detector v3Custom Code
Kolmogorov-Smirnov 2-sample test + CUSUM. Any of 4 signals fires → drift=true.
Methods: KS + CUSUM + EWMA
α: 0.05
34 · Mirror Agent LLM v3LLM Step
Sonnet introspects the metrics and proposes ONE concrete self-heal action.
Out: {sentence, proposed_action, urgency}
35 · Owner Notification v3Output
Sends the introspection + one-click self-heal to owner.
Channel: Telegram + dashboard card
30 · Error Budget Monitor v3Guardrail (continuous)
Runs continuously; when SLO budget exhausted → automatic feature freeze.
SLO: p50 15s · p99 45s · 99.5% avail
Budget: 3h 36m downtime/mo
